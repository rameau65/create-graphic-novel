# FONT_POLICY.md

## Graphic Novel & Webtoon Font Usage Policy

이 문서는 Webtoon & Graphic Novel 프로젝트에서 사용하는 폰트의 등록, 선택, 조판, 배포, 대체 및 품질 검수 기준을 정의한다.

## 1. 기본 원칙

1. 사용자가 특정 폰트를 첨부하거나 명시한 경우 해당 폰트를 최우선으로 사용한다.
2. 사용자가 폰트를 지정하지 않은 경우 프로젝트에 등록된 기본 폰트 목록에서 목적에 맞는 폰트를 선택한다.
3. 폰트 파일을 GitHub 저장소에 포함하기 전 반드시 해당 폰트의 재배포 및 프로젝트 사용 라이선스를 확인한다.
4. 라이선스가 불명확하거나 GitHub 공개 배포가 허용되지 않는 폰트 파일은 저장소에 직접 포함하지 않는다.
5. 폰트가 없는 환경에서도 결과물을 재현할 수 있도록 항상 대체 폰트(fallback)를 정의한다.
6. 가능한 경우 이미지는 clean art로 생성하고 텍스트는 후처리 단계에서 실제 폰트로 합성한다.

## 2. 권장 저장소 구조

```text
assets/
└── fonts/
    ├── README.md
    ├── LICENSES.md
    ├── korean/
    │   ├── serif/
    │   └── sans/
    └── display/
```

폰트별로 다음 정보를 `assets/fonts/README.md` 또는 `LICENSES.md`에 기록한다.

```text
font family:
file:
weight:
style:
source:
license:
redistribution allowed:
commercial use:
project role:
fallback:
```

## 3. 폰트 선택 우선순위

1. 사용자가 현재 작업에서 직접 지정한 폰트
2. 사용자가 현재 작업에 첨부한 폰트
3. 해당 작품의 기존 페이지에서 사용한 연속성 폰트
4. 프로젝트 GitHub에 등록된 폰트
5. 프로젝트 지정 fallback 폰트
6. 시스템에서 사용 가능한 유사 계열 폰트

작품 중간에 폰트를 임의로 변경하지 않는다.

## 4. 타이포그래피 역할

- **Title**: 표지 제목, 장 제목
- **Narration**: 내레이션, 철학적 문장, 설명
- **Dialogue**: 인물 대사
- **Emphasis**: 강조 문구
- **SFX**: 효과음

일반적인 그래픽노블에서는 1~2개 폰트 패밀리로 충분하며 과도한 폰트 혼용을 피한다.

## 5. 한글 조판 기준

- 한글 자모 및 완성형 글리프 누락 여부
- 따옴표, 괄호, 말줄임표, 대시 등의 형태
- 문장부호가 행의 시작에 부자연스럽게 놓이지 않는지
- 조사가 다음 행에 단독으로 떨어지지 않는지
- 한두 글자만 남는 짧은 마지막 줄이 반복되지 않는지
- 행간과 자간이 자연스러운지
- 제목과 본문의 위계가 명확한지
- 실제 최종 크기에서 읽을 수 있는지

자동 줄바꿈 결과를 그대로 사용하지 말고 필요한 경우 의미 단위로 직접 줄바꿈한다.

## 6. 스크립트 배치 원칙

### 6.1 텍스트 박스 최소화

그래픽노블 페이지에서는 사각형 텍스트 박스를 기본값으로 사용하지 않는다. 가능한 경우 이미지의 자연스러운 여백, 하늘, 벽, 바닥, 물, 그림자, 흐린 배경 등 시각 정보가 적은 공간에 스크립트를 직접 배치한다.

### 6.2 Hard No-Text Zones

다음 영역은 텍스트가 침범해서는 안 되는 보호 영역이다.

- 얼굴, 머리, 눈, 코, 입
- 몸통 및 주요 실루엣
- 손과 중요한 제스처
- 행동의 중심 영역
- 주요 소품과 상징적 오브젝트
- 음식, 도구, 차량, 반사 이미지
- 장면 이해에 필요한 배경 오브젝트

단순히 겹치지 않는 수준을 넘어 충분한 시각적 여유를 둔다.

## 7. 비율별 텍스트 공간 설계

### 3:4 Portrait

- 기본 그래픽노블 페이지 비율
- 상단 및 하단 여백 적극 활용
- 세로 리듬과 위→아래 읽기 흐름 유지
- 얼굴과 몸통을 피해 측면 또는 상·하단에 텍스트 배치

### 16:9 Landscape

- 시네마틱, 영상 프레임, 프레젠테이션형 그래픽노블
- 좌우 negative space 적극 활용
- 인물이 한쪽에 있으면 반대편을 텍스트 영역으로 우선 활용
- 중앙의 주요 인물 및 핵심 오브젝트 위에는 텍스트를 두지 않는다

기존 3:4 레이아웃을 단순 확대/축소하여 16:9로 변환하지 않는다. 비율 변경 시 텍스트 위치와 줄바꿈을 다시 설계한다.

## 8. 텍스트 컨테이너 사용 규칙

1. 텍스트를 여백으로 이동
2. 줄바꿈 수정
3. 텍스트 폭 조정
4. 컨테이너 크기 조정
5. 컨테이너 형태 변경
6. 페이지 구도 조정
7. 의미를 훼손하지 않는 범위에서 문장 압축
8. 마지막 수단으로만 글자 크기 소폭 축소

## 9. 폰트 크기와 가독성

최종 출력 크기, 매체, 폰트의 실제 한글 크기, 텍스트 길이, 페이지 밀도와 시청 거리를 함께 고려한다. 최종 결과를 실제 읽기 크기에서 검수한다.

## 10. 폰트 라이선스

GitHub 업로드 전 다음을 확인한다.

- 상업적 사용 허용 여부
- 수정 허용 여부
- 웹/앱/영상/인쇄 사용 허용 여부
- 재배포 허용 여부
- GitHub 공개 저장소 배포 허용 여부
- 폰트 파일 번들링 허용 여부
- 라이선스 또는 저작권 고지 의무

라이선스가 불명확하면 폰트 파일을 GitHub에 업로드하지 않고 family, 공식 출처, weight, 프로젝트 용도, fallback 정보만 저장한다.

## 11. Fallback Policy

```text
Korean Serif
Preferred → Project Serif → Noto Serif KR → system serif

Korean Sans
Preferred → Project Sans → Noto Sans KR → system sans-serif
```

대체 폰트 사용 시 줄바꿈, 크기, 자간, 행간, 정렬 및 캐릭터/오브젝트 충돌을 다시 확인한다.

## 12. 이미지 생성 모델과 폰트

```text
1. clean art 생성
2. protected visual zones 확인
3. text-safe negative space 결정
4. 실제 폰트 로드
5. 스크립트 합성
6. 최종 페이지 렌더링
7. 한글 글리프 및 충돌 QA
```

정확성이 중요한 한글 텍스트는 이미지 생성 결과를 그대로 신뢰하지 않고 후처리 타이포그래피로 교체하는 것을 우선한다.

## 13. 작품 연속성

```text
TITLE_FONT:
NARRATION_FONT:
DIALOGUE_FONT:
SFX_FONT:
TITLE_WEIGHT:
BODY_WEIGHT:
TITLE_ALIGNMENT:
NARRATION_ALIGNMENT:
PRIMARY_TEXT_COLOR:
SECONDARY_TEXT_COLOR:
FALLBACK_FONT:
```

## 14. 최종 QA

- 요청한 폰트가 실제 사용되었는가
- 잘못된 fallback이 발생하지 않았는가
- 한글 글리프가 깨지지 않았는가
- weight와 줄바꿈이 일관적인가
- 텍스트가 얼굴, 몸통, 손을 침범하지 않는가
- 텍스트가 핵심 오브젝트를 가리지 않는가
- 불필요한 텍스트 박스가 남아 있지 않은가
- 읽기 순서가 자연스러운가
- 3:4 또는 16:9 비율에 맞게 텍스트 위치가 설계되었는가
- 최종 읽기 크기에서 가독성이 충분한가
- 폰트 라이선스 및 임베딩 조건을 준수하는가

하나라도 충족하지 못하면 최종본으로 표시하지 않는다.

## 15. 프로젝트 기본 규칙

```text
사용자의 현재 명시적 지시
>
현재 첨부된 폰트
>
작품의 기존 Typography DNA
>
프로젝트 FONT_POLICY
>
프로젝트 기본 폰트
>
fallback font
```

텍스트 가독성과 스토리 이미지 보존이 충돌할 경우 캐릭터와 핵심 이미지 요소를 가리는 방식으로 해결하지 않는다. 텍스트 이동, 줄바꿈 변경 또는 negative space 재설계를 우선한다.
